# Gree GMV Cloud for Home Assistant

简体中文 | [English](README.md)

这是一个非官方 Home Assistant 自定义集成，用于接入通过微信小程序“格力中央空调微助手”提供云端控制的格力 GMV 中央空调项目。

本集成基于一套由设备所有者本人管理的实际系统开发：室外机为 `GMV-H200WL/H2S`，线控器为 `XC71-33/H2`，系统已安装蜂窝网络 DTU。它**不使用** Home Assistant 普通格力空调集成所采用的局域网协议。

## 当前状态与安全边界

- 通过格力未公开、无正式文档的私有 API 进行云端轮询和控制。
- 为项目中返回的每台室内机创建一个 climate 实体。
- 不自动收取短信验证码，不模拟微信协议，不执行账号或设备绑定，也不访问他人的设备。
- 不是本地控制：运行依赖格力云服务及系统中已有的蜂窝网络 DTU。
- 已在 Home Assistant Container 2026.7.1 和一套五分区系统上测试。
- 仍属于预发布软件；各房间完成校准前，仅建议在有人看护时使用。

本集成及其作者与珠海格力电器股份有限公司不存在隶属、授权或背书关系。

## 功能

- 每个房间独立开关。
- 制冷、制热、除湿、送风，以及仅主机可用的自动模式。
- `16–30 °C`、步进 `0.5 °C` 的目标温度。
- 默认自动风，并支持五个明确的固定风速目标。
- 房间每次真实地从关机变为开机时，默认使用自动风。
- 云端提供数据时显示房间温度或线控器温度。
- 提供在线状态、设定模式、服务器报告风速档位及故障标记等属性。
- 在 JWT 到期前六小时自动刷新 Bearer token。
- 凭据被云端拒绝时触发 Home Assistant 重新认证。
- 根据云端 `mainIDU` 字段自动识别主机。
- 根据当前可见的制冷或制热方向过滤主机、从机可选模式。

云端 API 会报告设定模式和开关状态，但没有经过验证的压缩机实际需求位。因此，本集成不会虚构“正在制冷”或“正在制热”的 `hvac_action`。

## 主机、从机与系统方向

已测试系统中有一台主线控器。只有主机可以选择自动模式，或在制冷与制热方向之间切换；从机永远不提供自动模式。系统处于制冷方向时，从机可选制冷、除湿和送风；系统处于制热方向时，从机可选制热和送风。

主机的自动模式仍会激活一个真实的制冷或制热方向：线控器上的自动灯会与相应的制冷或制热灯同时亮起。但抓包得到的 `getUnits` 响应只包含 `mode=5`，没有表示第二盏方向灯的字段。当一台正在运行的从机报告了制冷或制热模式时，本集成会据此判断当前系统方向。没有这种证据时，会同时保留制冷侧和制热侧选项，并提交一次控制请求，由 GMV 控制器决定接受或拒绝。明确的云端拒绝会显示在 Home Assistant 中，并立即刷新状态；传输结果不确定时绝不会自动重试写操作。

## 通过 HACS 安装

1. 打开 HACS，点击右上角菜单并选择 **Custom repositories（自定义存储库）**。
2. 添加 `https://github.com/bitcinnamon/gree-gmv-cloud-ha`，类别选择 **Integration**。
3. 下载 **Gree GMV Cloud**。
4. 重启 Home Assistant。
5. 打开 **设置 → 设备与服务 → 添加集成 → Gree GMV Cloud**。

HACS 只支持公开的 GitHub 存储库。本存储库刻意不包含任何账号凭据、抓包文件、设备标识、房间名称或小程序原始文件。

## 凭据

首次配置需要从设备所有者本人已经登录的小程序会话中取得三个值：

- `Authorization` Bearer token，可包含或省略 `Bearer ` 前缀；
- 微信 `openId`；
- 格力 `uid`。

普通的已认证请求：

```text
POST https://a.gree.com:7016/gree2/app/v2.0/control/getUnits
```

会在 `Authorization` 请求头中包含 Bearer token，并在表单请求体中包含 `openId` 和 `uid`。只能从自己的会话获取这些值。不要上传 HAR 文件，不要把凭据粘贴到 Issue，也不要提交 Home Assistant 的 `.storage` 目录。

实测 JWT 有效期为 72 小时。Home Assistant 持续运行时，本集成会在到期前刷新 token，并立即持久化保存替换后的值。如果刷新链中断，Home Assistant 只会要求输入新的 token，原有 `openId` 和 `uid` 会保留。

Home Assistant 会把 Config Entry 数据保存在配置目录中。请保护该目录及其备份；它不是专门的加密凭据保险库。

## 风速目标策略

当前版本小程序的控制协议会写入完整目标状态。状态响应与控制请求中的风速编码存在偏移，因此无法根据服务器报告的实际执行档位判断目标是否为自动风。对于尚未在 Home Assistant 中明确选择过风速的房间，本集成把自动风作为安全默认值。

明确选择的房间风速会覆盖默认值，并保存在 Home Assistant Config Entry 中，重启或升级后仍然保留。房间关机、处于主机自动模式或除湿模式时，修改风速只更新 Home Assistant 中保存的目标，不向云端写入。房间已经在制冷、制热或送风模式下运行时，选择风速会提交一次正常的完整状态请求，建议在线控器上确认结果。

每次写操作前，本集成都会重新读取最新云端状态。如果最新状态显示房间已关机，而本次操作将其开机，则完整控制请求固定使用自动风（`windSpeed=1`），同时把 Home Assistant 保存的目标更新为自动。对已经运行的房间重复发送开机请求，不会重置其当前风速目标。

当 Home Assistant 保存的是固定风速，而正在运行的室内机报告了不同的固定执行档位时，本集成会把它视为线控器上的人工调整：定期轮询时采用新档位，并在任何完整状态写入前再次核对。因此，修改温度不会把线控器刚调整的风速恢复成旧值。自动风不能从执行档位推断；一旦 Home Assistant 的目标明确为自动，就会持续保留为自动。

对于 HomeKit 与温控器关联的风扇，本集成提供单独的自动/手动状态，并使用 [Home Assistant 能识别的四个标准固定风速名称](https://github.com/home-assistant/core/blob/7c5eb60b7a98a3900cece9d8719f7a5620f459e7/homeassistant/components/homekit/climate_util.py#L27-L55)。固定风速条的 `25/50/75/100%` 分别对应 `1/2/3/5` 档。HomeKit 把 0% 保留为风扇未激活状态，而且 Home Assistant 会[丢弃单独的 0% 风速写入](https://github.com/home-assistant/core/blob/7c5eb60b7a98a3900cece9d8719f7a5620f459e7/homeassistant/components/homekit/climate_base.py#L219-L229)，因此 0% 不能作为第五个可写档位。

选择自动风，或在 HomeKit 提供该操作时关闭关联风扇，会发送自动风（`windSpeed=1`）；只有温控器的主电源开关才能真正关闭房间空调。房间本来已关机时，选择自动风只保存下次使用的目标，不会让空调开机。由于服务器没有返回自动风目标字段，HomeKit 选择自动后仍可能保留上一次固定风速条的位置。固定档位显示来自服务器最新报告：写入后三秒进行第一次检查，必要时在累计五秒时再检查一次；仍未确认时回退到真实报告档位。实际第 4 档仍可在 `reported_fan_level` 属性中看到，但在 HomeKit 中会显示为最接近的 75% 档位。

除湿和主机自动模式遵循当前小程序界面的限制，不能调整风速。房间关机或主机处于自动模式时，不允许修改温度。切换模式可能恢复该模式记忆的设定温度，因此每次写操作后本集成都会重新轮询实际状态。

## 已知限制

- 私有云端点可能随时变更或停止服务。
- 首次获取凭据仍需手动操作；本集成无法生成微信 `jsCode`。
- 尚未验证已经完全过期的 token 能否刷新。Home Assistant 长时间停机后可能需要重新导入 token。
- 版本 0.1.5 不会为初次配置后新增的室内机动态创建实体。
- 抓包响应中不存在主机自动模式的制冷或制热方向灯字段；其他 GMV 代际需要重新验证方向推断和相反方向拒绝逻辑。
- 控制请求中的风速值 `1..6` 与状态报告中的执行值 `3..7` 含义不同。五个固定执行档位只在当前测试系统上完成了校准；未配置目标时会有意使用自动风，而不会从执行风速反推目标。
- 官方小程序可以写入自动风，线控器也会执行；但离开页面后，小程序无法再次显示该目标。Home Assistant 同样没有服务器字段可以恢复自动风目标，因此只能持久化自己最近一次明确选择。
- 云端只报告执行档位，不报告目标类型，所以无法区分“线控器从固定风改为自动风”和“线控器改为当前相同执行档位的固定风”。在线控器或小程序做出这种修改后，请在 Home Assistant 或 HomeKit 中重新选择一次自动风。

## 卸载

在 **设置 → 设备与服务** 中删除该集成，通过 HACS 卸载并重启 Home Assistant。若要立即撤销云端会话，请退出官方小程序登录，或使用格力提供的账号会话管理功能。
